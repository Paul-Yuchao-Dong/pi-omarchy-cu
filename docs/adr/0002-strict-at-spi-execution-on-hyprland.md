# Strict AT-SPI Semantic Execution Without Compositor Input Fallbacks on Hyprland

On Omarchy (Hyprland Wayland), `agent-desktop`'s physical keyboard (`type`, `press`), pointer gesture (`double-click`, `hover`, wheel `scroll`), window management (`focus-window`, `close-app`), and `cmd+v` paste paths fail because `agent-desktop` only implements XTEST and GNOME Mutter RemoteDesktop. We decided to keep `pi-omarchy-cu` strictly on `agent-desktop`'s verified AT-SPI semantic actions and `wl-clipboard`, pruning dead X11/Mutter operations from Jev's decision space and offering text entry (`set-value`) only on nodes that explicitly advertise `SetValue`, rather than shelling out to unverified compositor-level input tools (`wtype`, `hyprctl`) that bypass AT-SPI target identity and post-state verification.
